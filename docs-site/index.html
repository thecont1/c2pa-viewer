C2PA Verify API

Verify content authenticity programmatically: C2PA manifest validation, trust-chain verification against the official trust lists, provenance extraction, and nutritional-label metadata — as a synchronous API, an asynchronous job pipeline for large assets, or an MCP server for AI agents.

Base URL: https://api.c2pa.thecontrarian.in  ·  OpenAPI 3.1: GET /v1/openapi.json

Quickstart

1. Get a free key at the dashboard (500 verifications/month, no card required) or programmatically:

curl -X POST https://api.c2pa.thecontrarian.in/v1/signup/free \
  -H 'content-type: application/json' \
  -d '{"turnstile_token": "<token from the Turnstile widget>"}'

2. Verify an image:

curl -X POST https://api.c2pa.thecontrarian.in/v1/verify \
  -H "authorization: Bearer c2pa_live_…" \
  -H 'content-type: application/json' \
  -d '{"url": "https://example.com/photo.jpg"}'

3. Read the verdict: status is one of trusted, valid_untrusted, invalid, unverified.

Authentication

Every endpoint except the public ones uses a bearer key: Authorization: Bearer c2pa_live_…

Key kindPrefixBehavior
Livec2pa_live_Production. Counted against monthly quota.
Testc2pa_test_Sandbox — only accepts the fixture corpus, never metered.

Keys are shown exactly once at creation — only their SHA-256 hash is stored. Lost keys cannot be recovered; rotate instead (POST /v1/key/rotate needs the current key, so protect it).

Rate limit: 60 requests/minute per key (429 rate_limited with Retry-After).

Exhaustion returns 429 quota_exceeded; the count resets on the UTC month boundary. Job submissions charge at acceptance — a job that later fails is not refunded.

Verify synchronously

POST/v1/verify

Full verification of one asset up to 20 MiB. Input is one of:

  • JSON url: {"url": "https://…"} — the service fetches with SSRF protection (redirects re-validated, private hosts blocked)
  • JSON base64: {"data": "…", "mime": "image/jpeg", "filename": "photo.jpg"}
  • multipart/form-data: a file field

Query parameters: include (sections: exif,iptc,gps,thumbnails,raw_manifest; default exif,iptc), trust (c2pa or c2pa_and_itl, default the latter), strip_gps (default true).

The response is the full VerifyResult — validation state, trust basis, active manifest, claim generator, signer chain, provenance rows, EXIF/IPTC sections, thumbnails, and the asset digest. See the schemas in the OpenAPI document.

GET/v1/verify/mini?url=… — compact trust card (the same payload the viewer's nutritional label uses).

Need more than 20 MiB, or files that take a while to fetch? Use async jobs — the ceiling there is 1 GiB.

Async jobs

POST/v1/jobs — submit; GET/v1/jobs/{job_id} — poll; GET/v1/jobs — list.

Two input modes:

  • URL job: {"url": "https://…", "filename": "x.jpg"} — accepted instantly, fetched server-side
  • Direct upload: omit url — the response is awaiting_upload with a presigned PUT session; upload the bytes, R2 notifies the pipeline automatically
curl -X POST https://api.c2pa.thecontrarian.in/v1/jobs \
  -H "authorization: Bearer c2pa_live_…" -H 'content-type: application/json' \
  -H 'Idempotency-Key: order-4173' \
  -d '{"url": "https://example.com/big.jpg", "filename": "big.jpg",
       "webhook_url": "https://you.example/hooks/c2pa"}'

States: queued → processing → succeeded | failed. The terminal job object embeds the full VerifyResult in result or an RFC 9457 problem in error.

Idempotency: send Idempotency-Key; a replay returns the original job (200 instead of 202) instead of charging a second verification.

Webhooks

Attach webhook_url at job creation. Delivery is at least once: the callback is retried after non-2xx responses, transport errors, or a 30-second timeout, up to four attempts total. Deduplicate by job identifier — the same terminal state may be delivered more than once. The callback is signed:

X-C2PA-Signature: t=1732300800,v1=<hex>

v1 is HMAC-SHA256 of the string "<t>.<raw body>" keyed by the webhook signing secret (available on the dashboard while rotating a key — store it when issued). Verify the timestamp is fresh (5 minutes), then compare constant-time.

Rotation inherits tier, quota, scopes and the Stripe billing linkage — a rotated paid key never loses its subscription.

Billing

Paid tiers run through Stripe checkout. Two flows:

  • Upgrade in place — POST /v1/billing/checkout {"tier":"pro"} with your key: the same key becomes paid, plaintext unchanged.
  • New customer — checkout without a key (dashboard handles this): after payment the success page reveals a fresh key exactly once via GET /v1/billing/reveal?session_id=…. The key is provisioned at reveal time — plaintext never rests at storage anywhere.

Manage payment methods, invoices and cancellation through POST /v1/billing/portal (Stripe customer portal). Cancellation downgrades the key to free at the end of the subscription; failed payments mark it past_due but never hard-cut service.

Trust lists

GET/v1/trust-lists (public) — provenance and digests of the vendored trust lists. The trust parameter on verification selects which lists may produce a trusted verdict; trust.basis in the result reports which list actually matched.

Errors

Every error is RFC 9457 application/problem+json with a machine-readable code:

StatuscodeMeaning
401unauthorizedMissing/malformed/unknown key
403forbiddenRevoked key, sandbox violation, Turnstile failure
404job_not_foundUnknown job — or another key's job (ownership isolation)
413payload_too_largeAsset over the 20 MiB sync cap
415unsupported_media_typeFormat the engine cannot read
422invalid_requestMalformed input, unparseable asset
429rate_limited / quota_exceededPer-minute limit / monthly quota
502upstream_fetch_failedThe asset URL could not be fetched
503billing_not_configuredDeployment has no billing provider attached

SDKs

Thin idiomatic clients — no dependencies beyond the platform fetch/HTTP:

  • TypeScript: sdk/typescript — works in Node 18+, Bun, Deno, workers
  • Python: sdk/python — 3.9+, stdlib only
import { C2paClient } from 'c2pa-verify';
const api = new C2paClient('c2pa_live_…');
const result = await api.verify({ url: 'https://example.com/photo.jpg' });
console.log(result.status);
from c2pa_verify import C2paClient
api = C2paClient('c2pa_live_…')
result = api.verify(url='https://example.com/photo.jpg')
print(result['status'])
