Data Processing Addendum

C2PA Verify API · Effective 2026-11-26 · Draft v1 — pending legal review before commercial launch

This Addendum forms part of the Terms of Service where a customer processes personal data through the C2PA Verify API. The customer is the data controller; the Service operator is the data processor.

1. Subject matter and nature of processing

Processing consists of: receiving digital assets (or references to them), parsing embedded C2PA manifests and metadata, validating signatures and trust chains, and returning structured verification results. The Service acts on documented instructions only — the API contract — and does not determine purposes beyond verification.

2. Categories of data

The Service is designed for media files, not personal data. However, assets can incidentally contain personal data: faces in images, author names in C2PA manifests, capture locations in EXIF GPS fields. GPS coordinates are stripped from results by default (strip_gps=true) and we recommend keeping that default. Customers should not submit assets whose principal purpose is processing personal data.

3. Processor obligations

  • Process personal data only on documented instructions (the API contract and these terms).
  • Ensure persons with access are bound by confidentiality; access is limited to operational necessity.
  • Apply the retention limits in the Data Retention Statement, including automatic 30-day deletion of asynchronously processed assets and never storing synchronously verified assets.
  • Not engage sub-processors for asset content beyond the infrastructure providers listed below; changes will be announced on the documentation site with 14 days to object.
  • Assist the controller, within reasonable scope, with data-subject requests — noting that assets are not indexed by person and most personal data transits without persistent storage.
  • Notify the controller without undue delay of any personal-data breach affecting their assets, with reasonable information for the controller's own obligations.

4. Infrastructure sub-processors

  • Cloudflare, Inc. — compute (Workers, Containers, Durable Objects), storage (R2, D1), network. Processing occurs across Cloudflare's network; Cloudflare's own DPA applies to its processing.
  • Stripe, Inc. — billing identity and payment metadata for paid keys. Stripe never receives asset content.

5. International transfers

Cloudflare's network is global; verification compute runs in the point of presence nearest the caller unless configured otherwise. Customers requiring strict regional processing should contact us before subscribing — regional constraints are not part of the standard tiers.

6. Security measures

  • API keys exist only as SHA-256 hashes at rest; plaintext is never stored.
  • All transport is TLS; internal object storage is private with short-lived presigned upload sessions.
  • Quota enforcement and key state use strongly consistent per-key serialization (Durable Objects).
  • SSRF protections on all outbound asset fetching: scheme allowlist, private-host blocking, per-redirect revalidation, size caps.
  • Security-relevant configuration changes (trust lists, engine versions) are versioned and auditable in source control.

7. Termination

On key revocation or subscription end, associated job records and usage aggregates are retained per the retention schedule for audit, then deleted. Assets in object storage continue to auto-delete on the 30-day lifecycle regardless of account state.
