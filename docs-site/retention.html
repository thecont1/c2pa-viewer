Data Retention Statement

C2PA Verify API · Effective 2026-11-26 · Describes enforced behavior, not intent

This statement describes exactly what the Service stores and for how long. Where deletion is enforced automatically by infrastructure lifecycle rules, that is stated explicitly.

Assets and verification results

DataStorageRetention
Assets submitted to synchronous verification (POST /v1/verify)None — processed in memoryNot stored; discarded when the response completes
Assets fetched or uploaded for asynchronous jobsObject storage (Cloudflare R2)Deleted automatically after 30 days by enforced bucket lifecycle rules
Verification results of asynchronous jobsObject storage (R2) and job metadata (D1)Object copies deleted after 30 days; the result embedded in the job record follows job-record retention below

Operational records

DataContentsRetention
Job recordsJob id, status, source URL/filename, timestamps, result or errorUp to 12 months, for support and abuse investigation
Usage aggregatesMonthly verification counts and byte totals per keyUp to 24 months, for billing and quota audit
API keysSHA-256 hash of the key, display prefix, tier, quota, billing linkage — never the plaintextUntil revoked, plus 12 months for audit
Platform logsRequest logs, error traces (Cloudflare Workers observability)Cloudflare's standard log retention; asset bytes are never logged

What is never stored

  • Plaintext API keys — only their SHA-256 hashes exist at rest. Keys cannot be recovered if lost; rotation is the recovery path.
  • Asset bytes from synchronous verification.
  • GPS coordinates in verification results when strip_gps is enabled (the default).

Deletion requests

Because assets are input-transient and auto-deleted within 30 days, most erasure requests are satisfied by the pipeline itself. Job records and usage aggregates tied to a key are deleted when the key is revoked on request — contact the address published on the documentation site.
