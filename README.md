# C2PA Viewer

**What is this?** Photos and images increasingly carry a hidden "nutrition label"
called [C2PA content credentials](https://contentcredentials.org/) — a tamper-proof
record of where an image came from: which camera or AI tool created it, what edits
were applied, and when. This project lets you read those labels.

## What it can do for you

**Check any image in your browser, for free, at [c2pa.thecontrarian.in](https://c2pa.thecontrarian.in/)** —
drop a file or paste a link and instantly see:

- **Is it really what it claims to be?** A green "Authenticity Verified" badge
  means the image's credentials are cryptographically intact *and* signed by a
  trusted authority — not just any signature.
- **Camera or AI?** The viewer tells you whether an image came out of a real
  camera (including RAW files), or was generated by AI tools like Firefly,
  DALL-E, or Midjourney.
- **The full history** — every recorded edit, with timestamps and details
  ("Clarity: +20", "Blacks: -5"), plus what tools were used.
- **All the photography details** — camera, lens, exposure, aperture, ISO,
  and the rest of the embedded metadata, formatted the way photographers
  expect to read it.
- **Private by default** — the analysis happens entirely in your browser.
  Nothing is uploaded. GPS locations are stripped from shared output.

## For developers: the verification API

The same engine is available as a commercial API
(`api.c2pa.thecontrarian.in`) so your own software can verify images
automatically — with TypeScript and Python SDKs, plus an MCP server so AI
agents can verify images natively. It works in two modes:

**Sync** — one request, one response, in about the time it takes to blink.
*Example: a photo-sharing community moderating uploads.* A user uploads a
profile photo; before accepting it, your server calls the API and waits a
fraction of a second. You immediately know whether it's camera-signed,
AI-generated, or stripped of provenance — and badge or flag it in the same
request. This covers most integrations.

**Async** — submit a batch of jobs, disconnect, and receive results as
signed webhooks (or poll for them). *Example: a newsroom verification desk
scanning wire feeds at scale.* Thousands of images a day arrive from
freelance photographers as URLs to originals on their servers. Instead of
holding thousands of connections open, you fire off job batches and your
webhook endpoint receives each signed result as it completes — retried
automatically if your endpoint hiccups. Nothing blocks, nothing is lost.

**Rule of thumb**: sync when you already hold the image and need the answer
in-line; async when volume, file counts, or slow sources make waiting
expensive.
